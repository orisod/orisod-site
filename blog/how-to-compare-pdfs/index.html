How to Compare Two PDFs (and What "Compare" Actually Means)

"Compare these two PDFs" sounds like one request, but it hides a real question: compare them as what — as pictures, or as words? Almost every practical PDF-comparison tool, including this one, answers "as words," and understanding why changes what you should expect from the result.

Two very different ideas of "compare"

A pixel-level comparison would render both PDFs to images and diff the images themselves — technically possible, but brittle in practice: a document re-exported at a slightly different resolution, with antialiasing turned on or off, or with a font substituted for a missing one, would show up as "different" everywhere even if the words are identical. A text-level comparison instead pulls out each PDF's underlying selectable text and compares that — immune to rendering noise, but blind to anything that isn't text: a moved image, a recolored heading, a swapped font are all invisible to it. Neither approach is "the" correct one; they answer different questions, and a text diff is the one that matches what most people actually mean when they ask "what changed in this document."

How the extracted text becomes lines

A PDF's text isn't stored as lines — it's stored as a sequence of positioned text runs, the same fact that makes word wrap something a PDF generator has to build itself. Reconstructing lines for a comparison means walking through those runs in order and watching for the flag a PDF-reading library reports whenever a run is meant to be followed by a line break, grouping every run up to that point into one line of text. It's an approximation — a PDF that encodes its line breaks unusually can produce coarser lines than expected — but it's a reasonable one for the vast majority of ordinary documents.

What a line-by-line diff is actually computing

Once both PDFs are broken into a list of lines, the comparison problem becomes: find the longest sequence of lines that appears, in the same order, in both lists. Every line in File A that isn't part of that shared sequence is something removed; every line in File B that isn't part of it is something added. This is the same core idea — the "longest common subsequence" — that powers `git diff` and every other line-based diff tool; a PDF comparison tool doesn't need to invent a new algorithm, just a way to turn PDF pages into line lists that algorithm can consume.

Why the result can still surprise you

Because the comparison is purely textual, a handful of situations produce results that are technically correct but easy to misread. A paragraph reflowed differently — same words, different line breaks — can show as several removed and added lines even though no wording actually changed, since the diff compares whole reconstructed lines, not the underlying sentences. A scanned page with no real text layer contributes nothing to compare at all, silently, unless the tool explicitly flags it. And a change to color, font, or image placement never appears, because none of that is text in the first place.

Quick answers

Will formatting-only changes (bold, color, font) show up? No — a text-based comparison only sees the characters, never how they're styled or laid out.

Why does "ignore whitespace" matter for PDFs specifically? PDF text extraction sometimes inserts slightly different spacing between runs depending on how the original document encoded them, so two functionally identical lines can differ by a stray space unless whitespace differences are deliberately ignored.

Is this the same thing Word's "Compare Documents" feature does? Conceptually yes — both reduce a document to text and diff it — but a PDF has already lost the paragraph/style metadata a word processor's native format keeps, so a PDF-to-PDF comparison works purely off reconstructed lines instead.

A PDF comparison tool isn't reading the document the way a person does — it's reducing it to a list of lines and asking a well-known question about two lists. Knowing that turns a surprising diff into an expected one: it only ever tells you what changed in the words, never in the way they were dressed up.
