How to Generate a Strong Password (and Why Length Matters More Than Tricks)

Swapping letters for symbols — "password" becomes "P@ssw0rd" — feels like it should make a password much harder to crack. In practice, it barely moves the needle, while making the password harder for you to remember. What actually determines how hard a password is to guess is simpler, and more mathematical, than clever substitutions.

What "strength" actually measures

A password's strength is usually measured in bits of entropy — roughly, the number of guesses a brute-force attacker working through every possibility would need, expressed as a power of two. Every character position multiplies the total number of possible passwords by however many characters could go there. A password built from a bigger pool of possible characters, or one that's simply longer, has exponentially more combinations to search through — and length affects that exponent far more directly than character variety does.

Why substitutions don't help as much as they feel like they should

Swapping "a" for "@" or "o" for "0" barely changes the brute-force math, and it does essentially nothing against how real attacks actually work. Attackers don't try every possible string in order — they try dictionaries of real words first, then apply exactly these common substitution patterns to each one, because so many people use them. "P@ssw0rd" isn't meaningfully harder to guess than "password" against a real attacker; it's just harder for you to type correctly.

What length alone buys you

Going from an 8-character password to a 16-character one, keeping the same character pool, nearly doubles the entropy bit count in the chart above — and because entropy is measured on a doubling (bits) scale, that near-doubling represents squaring the actual number of possible passwords, not just doubling it. Adding a longer, still-random tail to a password does more for its real-world strength than any amount of character substitution on a short one.

Why a password manager changes the calculation entirely

None of this matters if you have to remember and type the password yourself — a 20-character fully random string is unusable without help. A password manager removes that constraint: it generates and stores a long random password per site, and you only need to remember one master password to unlock it. That's what actually makes maximum-entropy, no-compromises passwords practical for everyday use.

Quick answers

Should I still add symbols to my password? It doesn't hurt, but if you're choosing between a longer password with fewer character types or a shorter one packed with symbols, length wins by a wide margin.

Is a random password actually better than a memorable passphrase? A long passphrase built from several truly random, unrelated words can reach similar entropy while staying typeable — the key word is random; a quote or common phrase is guessable regardless of length.

How long should a password be? 16 characters from a full character set is a reasonable default for most accounts; use your password manager's maximum where a site allows it.
