How to Convert HTML to PDF (Paste Code, Get a File)

You have an HTML snippet, an invoice template, or a styled report and need it as a fixed, shareable PDF instead of raw code. Converting HTML directly to a PDF, without installing anything or standing up a server, turns styled markup into a document in a few seconds.

How HTML-to-PDF conversion actually works

The HTML you provide gets rendered exactly like a browser would render it — layout, colors, fonts, everything defined in inline styles or <style> blocks — and that rendered result is then captured and placed into a PDF. It's effectively taking a high-resolution "screenshot" of the rendered page and packaging it as a document, rather than parsing the HTML into some intermediate PDF-specific format.

What it can and can't do with a live website

A common assumption is that you can hand a tool a URL and get back a PDF of that page — but a browser-based converter with no server behind it can't fetch another website's page for you; that would require server-side infrastructure to make the request. What it can do is convert HTML code directly, which means the workaround for converting a live page is straightforward: view the page's source, copy the relevant HTML, and paste it in.

Why some images don't show up

An image referenced by URL from another website needs that website to explicitly allow cross-origin access for the browser to read its pixel data — without that permission, the browser can see the image but can't include its contents in a captured render. This is a browser security restriction (CORS), not a bug in the conversion process, and it mainly affects images hosted elsewhere rather than ones embedded directly as data.

How pagination works for long content

Content taller than a single printed page needs to be split across multiple pages, and the straightforward way to do that is a direct cut at a fixed height — page 1 gets the first slice, page 2 the next, and so on, with no gap or overlap between them. This works cleanly most of the time, especially with naturally spaced content like headings and paragraphs, but it's a geometric cut rather than layout-aware pagination — a line of dense text sitting exactly on that cut point could, in principle, be split visually between two pages.

Choosing page size and orientation

A4 and Letter cover most standard documents; Legal is common for contracts and certain forms. Orientation matters more than it might seem — a wide table or a landscape-oriented design will look cramped and awkward forced into a tall portrait page, while portrait suits regular text content. Getting these settings right before converting saves a re-download later.

A concrete example

You built a simple styled invoice as an HTML file — a logo, some CSS for spacing and colors, a table of line items — and need to send it as a PDF rather than an editable web page. Pasting the HTML in, confirming the preview looks right, and converting produces a fixed PDF version in seconds, with no design software or server-side rendering pipeline involved.

Quick answers

Can I convert a live website by giving its URL? Not directly — a browser-based tool with no server can't fetch another site's page. Copy that page's HTML source and paste it in instead.

Why are some of my images missing from the PDF? They're likely loaded from a site that blocks cross-origin access, which prevents the browser from reading their pixel data.

Will a line of text ever get cut in half across a page break? It's possible with dense content, since page breaks are a fixed-height cut rather than reflow-aware pagination — content with natural spacing (headings, list items, paragraph gaps) almost always avoids this.
