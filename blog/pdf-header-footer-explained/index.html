How to Add a Header or Footer to Every Page of a PDF

A header or footer is just text drawn in the margin of every page — but getting from "I want my document title at the top of each page" to an actual PDF means understanding a few things a word processor normally hides from you entirely.

A PDF page doesn't have a "header area" built in

Word processors have a dedicated header/footer editing mode because their file format tracks that concept explicitly — a header is its own object, repeated automatically across pages. A PDF doesn't work that way. Once a document is exported to PDF, every page is just a flat collection of positioned text and graphics; there's no special "this is the header" flag on anything. Adding a header or footer to an existing PDF means placing new text at a specific coordinate near the top or bottom of every page — visually a header, but structurally identical to any other text on the page.

Why the same line has to be recalculated on every page

Because there's no shared header object, adding one line of header text to a 50-page document means literally drawing that same text 50 separate times, once per page — and if the text should be centered, its horizontal position has to be recalculated per page too, since centering depends on the pixel width of the rendered text (which varies by content) and the width of that particular page (which can technically differ page to page, even within one PDF). None of this is visible to someone just typing "Confidential" into a header field — it's handled automatically — but it's exactly what a tool has to do under the hood.

What a token like {page} actually does

Typing a literal page number into a header would mean re-typing a different number for every single page, which defeats the point. Instead, header/footer text is treated as a small template: a placeholder like {page} stays in the text as typed, and only at the moment each page is actually rendered does the tool substitute in that page's real number — {page} becomes 1 on the first page, 2 on the second, and so on, while {pages} is substituted with the same total page count everywhere. A line like Page {page} of {pages} is really just three pieces glued together: static text, a per-page substitution, and a document-wide constant.

Why this is a separate tool from Add Page Numbers

A tool that only stamps a bare number in a corner is deliberately simpler than one that draws arbitrary header/footer text — it doesn't need a text field, alignment options, or a template system, because there's exactly one thing to configure: which corner. Folding full header/footer text into that same tool would mean either overcomplicating the simple case or under-serving the flexible one. Keeping them separate means someone who just wants a page number gets a two-click tool, and someone who wants "Confidential Draft — {date}" across the top of every page gets the flexibility that actually requires.

Quick answers

Can a header and footer have different alignment or text? Yes — they're independent by design, since a title at the top and a page count at the bottom are two unrelated pieces of information that happen to share the same "repeated on every page" mechanism.

Why is the date format fixed instead of matching my region? A date written as 03/04/25 means a completely different day depending on whether the reader expects month-first or day-first order. A fixed, unambiguous format avoids that confusion entirely, at the cost of not matching everyone's personal preference.

Does adding a header/footer flatten or rasterize the PDF? No — the new text is drawn as real vector text using the same mechanism as the rest of the page, so it stays selectable and the existing content is untouched.
