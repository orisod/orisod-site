How This Browser-Based Collage Maker Actually Works

A collage tool that runs entirely client-side has to solve a few problems a design-app collage feature doesn't: the same layout has to render two different ways (fast enough to drag in real time, and pixel-exact for a 3000px export), and none of it can lean on a server to do the slow part. Here's what actually happens between dropping in photos and downloading a PNG.

Why the grid is computed as plain rectangles, not CSS Grid auto-placement

The obvious way to build a "2 to 9 photos in a grid" layout is CSS Grid: define columns and rows, let the browser place each cell. That works fine for what's on screen — but the moment you also need to render the exact same layout onto an export canvas at, say, 3000px wide, you're stuck re-implementing the browser's own grid-placement algorithm in JavaScript to get identical positions. Any tiny mismatch between the two shows up as a shifted seam between two photos in the downloaded file. Instead, every layout here is defined as a small list of column/row spans, and one function turns that into plain x/y/width/height rectangles given a target canvas size. The live preview positions each photo cell with those numbers; export does the exact same math at a different resolution. Same function, same output shape, no drift.

Why the live preview and the final export aren't the same code path

Re-drawing a full canvas — filters, rounded corners, grain, text — every time a zoom or spacing slider moves would be slow enough to feel laggy, especially with nine photos on screen at once. The live grid instead uses real CSS: each photo sits in an absolutely-positioned cell, filtered with the CSS filter property, clipped with border-radius — all of it GPU-composited and effectively free to redraw on every input event. Only when you actually download does the tool build a full-resolution canvas from scratch, using the browser's Canvas 2D ctx.filter property (which accepts the same filter syntax as CSS) so the exact same brightness/contrast/saturation/sepia/hue values apply identically in both places.

Why filters are baked in per photo, not applied once to the finished collage

Applying one filter to the whole finished image would be simpler to build, but it also means every photo in the collage has to share the same look — which falls apart the moment you're combining a bright outdoor shot with a dim indoor one. Each photo instead carries its own filter choice and its own brightness/contrast/saturation offsets, stored per photo rather than per collage. Selecting a different grid cell swaps which photo's settings the filter panel and sliders are editing; nothing about the layout or the other photos changes.

Why 30-plus filters took more tuning than picking 30 numbers

A CSS filter preset is just a handful of numbers — brightness, contrast, saturation, sepia, grayscale, a hue rotation, sometimes blur. It's easy to generate dozens of presets that are all technically different and still look nearly identical, especially within a themed group like "vivid" or "muted," where the whole point is a family resemblance. Getting presets that are actually easy to tell apart at a glance took pushing the values further apart than felt intuitive at first, and in one case, undoing a mistake entirely: an early pass used a large hue-rotation (past 180 degrees) for a couple of "cool" presets, which doesn't shift a photo toward blue the way you'd expect — past a certain point a hue rotation wraps around and can shift blue skies toward magenta instead, which reads as broken, not cool-toned. The fix was smaller, more conservative hue shifts for anything meant to look literally warmer or cooler, and saving the more aggressive hue rotation for presets that are supposed to look deliberately unusual, like a cross-processed film look.

Why some presets add grain and most don't

Color grading alone — adjusting brightness, contrast, saturation — can get a photo most of the way to looking vintage, but it can't reproduce the visible texture of actual film grain, which is a property of the image's fine detail, not its overall color. Presets meant to look like scanned film or an old print layer a second effect on top of the color grading: a texture generated at render time (random per-pixel noise, not a fixed image file) and blended over the photo at low opacity. Generating it on the fly instead of shipping a texture image means there's no repeating pattern to notice and no extra file to load — it costs a few milliseconds of canvas drawing instead.

Why reordering uses the browser's native drag-and-drop instead of a custom version

Dragging a photo from one grid cell to another to swap their positions is handled with the same dragstart / dragover / drop events used elsewhere on this site for page-reordering tools, rather than a hand-built pointer-tracking system. It's less code, and it's a browser capability instead of one more thing to maintain.

Quick answers

Why can filters only be brightness/contrast/saturation/sepia/grayscale/hue/blur, and not more exotic effects? Those are the values the CSS/Canvas filter property actually supports natively, with no image-processing library involved. Effects outside that set (like real film grain) are added as a second layer on top, not folded into the filter string.

Why is there a separate zoom and pan per photo instead of one crop tool? Each photo's position inside its cell — how zoomed in it is, and where it's centered — is stored independently, so moving one photo around never affects any other cell's framing, even after you change the grid layout.

Does a higher export resolution use a different rendering path than the preview? No — it's the exact same rectangle-and-filter math, just run once at a bigger target size. There's no separate "high quality mode."

Why is the background limited to a solid color for now? A solid color is one CSS/canvas fill; a gradient or image background would need its own positioning and scaling rules layered under everything else, which is a reasonable feature to add later but wasn't essential for a first version.
