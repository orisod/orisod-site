Cómo se convierte HTML a Markdown

Un conversor lee la estructura HTML y aplica reglas a encabezados, énfasis, enlaces, listas, código y otros elementos compatibles. Como Markdown tiene varios dialectos y menos funciones, el resultado es una simplificación controlada, no una traducción perfectamente reversible.

Un recorrido de árbol, no una transformación de texto

El navegador no le entrega a un conversor texto HTML crudo para buscar patrones; le entrega el DOM, la estructura de árbol ya interpretada que el navegador construyó para renderizar la página: este párrafo contiene este span en negrita, que contiene este nodo de texto, y así sucesivamente. Un conversor recorre ese árbol de arriba hacia abajo, y para cada nodo que encuentra, hace una pregunta: ¿qué sintaxis de Markdown representa este elemento específico? Un `<strong>` se convierte en texto envuelto en `**`, un `<h2>` se convierte en una línea que empieza con `##`, un `<a>` se convierte en `[texto](url)`. El resultado se construye convirtiendo recursivamente primero los hijos de cada nodo, y luego envolviendo el resultado con la sintaxis que exige la etiqueta de ese nodo.

Por qué esto es un mapeo, no una traducción

Cada elemento HTML necesita una regla explícita que diga en qué Markdown se convierte; no existe una forma automática o de propósito general de derivar uno del otro, porque Markdown no fue diseñado para representar todo lo que HTML puede. Un `<div>` con una clase CSS personalizada no tiene ningún equivalente en Markdown; un conversor simplemente lo trata como un envoltorio invisible y conserva su contenido. Por eso un conversor maduro incluye decenas de reglas integradas (una por cada etiqueta común) y permite registrar más para cualquier cosa inusual que encuentre.

Por qué una tabla necesita una fila de encabezado para convertirse siquiera

Las tablas con barras pertenecen a extensiones populares de Markdown, no a la especificación básica original. Un conversor puede tomar la primera fila como cabecera, conservar HTML crudo o usar otra representación. La ausencia de no vuelve universalmente imposible la conversión.

Qué nunca sobrevive al viaje

Colores, fuentes, scripts, diseños complejos y muchos atributos no tienen equivalentes portátiles. La herramienta puede descartarlos, conservar HTML crudo o usar extensiones. La sanitización es otro asunto de seguridad, especialmente con HTML no confiable.

Qué revisar después de convertir

¿Por qué el contenido pegado a veces trae formato inesperado? El pegado de texto enriquecido desde apps como Word o Google Docs suele envolver el contenido en elementos de estilo extra que la app añadió para su propio renderizado; un conversor sigue extrayendo la estructura subyacente correctamente, pero un formato de origen muy inusual puede producir ocasionalmente un resultado más ruidoso que un HTML limpio.

Un enlace sin etiqueta carece de ancla visible útil. La herramienta puede crear un enlace vacío, usar la URL como texto o descartarlo según sus reglas.

¿La conversión de HTML a Markdown es reversible? No perfectamente; convertir Markdown de vuelta a HTML recupera la estructura, pero cualquier cosa que Markdown no pudiera representar desde el principio (estilo personalizado, diseño) ya se perdió y no puede reconstruirse solo a partir del Markdown.
