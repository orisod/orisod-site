Cómo funciona la reparación de PDF y qué no puede recuperar

«Este PDF no se abre» describe un síntoma, no un diagnóstico. El índice puede estar equivocado, un objeto puede tener una sintaxis inválida, la descarga puede estar incompleta o el archivo quizá solo requiera contraseña. Reparar comienza por distinguir esos casos.

Los objetos y el índice del PDF pueden fallar por separado

Un PDF contiene objetos numerados para páginas, fuentes, imágenes y otros recursos. Una estructura de referencias cruzadas, conocida como xref, registra dónde están guardados; el tráiler dirige al lector hacia la raíz del documento. Que el mapa esté dañado no significa necesariamente que el contenido haya desaparecido.

Algunos lectores reconstruyen un índice dañado

Muchos motores pueden buscar marcadores de objetos cuando la información xref no es fiable. Si los objetos están intactos, el lector puede abrir el archivo sin una reparación explícita o reescribirlo con otro índice. Los analizadores no se comportan igual; un PDF puede abrirse en un visor y fallar en otro.

Los objetos malformados plantean otro problema

Encontrar un objeto no garantiza que pueda decodificarse. Diccionarios rotos, flujos inválidos o longitudes incoherentes pueden hacer que se rechace ese componente. Un proceso tolerante quizá conserve lo legible y omita lo dañado, pero esa omisión puede eliminar una imagen, fuente, anotación o dependencia de página.

La reparación no recrea bytes ausentes

Una descarga truncada puede terminar antes de guardar páginas o flujos completos. Ningún algoritmo puede inferir los bytes exactos que faltan. Solo recuperará las estructuras todavía legibles y el documento puede quedar incompleto aunque vuelva a abrirse.

Una validación independiente encuentra fallos distintos

Abrir el resultado con otro motor PDF aporta una comprobación útil porque cada analizador tiene tolerancias diferentes. No demuestra que todos los objetos sean correctos. Compara páginas y contenido visible, y prueba el texto, enlaces, formularios o adjuntos importantes.

Qué significa el resultado de la reparación

Si mi PDF tiene un índice dañado, ¿la reparación lo "arreglará"? Normalmente no hay nada que arreglar; un lector construido para escanear el archivo directamente ya evita por sí solo un índice roto, así que un archivo así típicamente vuelve como "no se detectaron problemas" en lugar de "reparado". Eso no es que no se detecte el daño; el daño simplemente nunca impidió que el archivo se pudiera leer.

El archivo reparado puede tener menos páginas si se dañaron su árbol de páginas u objetos necesarios. Compáralo con una copia conocida cuando sea posible.

¿Puede la reparación arreglar un PDF que no se abre porque está protegido con contraseña? No; ese es un problema de control de acceso, no de daño. Los objetos del archivo pueden estar perfectamente bien; simplemente al lector no se le permite verlos sin la contraseña, lo cual es un tipo de "no se abre" completamente distinto.

El resultado es una reconstrucción, no una promesa de identidad byte por byte. Guárdalo como otro archivo y conserva la fuente dañada para futuros intentos.
